# Generated keymap reference — design

Date: 2026-08-04
Status: approved (discussion in session "layer-diag"); goal: ship both phases
Covers: TODO #1 "Generate clean schemes from layer definitions (kill manual drift)"
and TODO #3 "Document leader sequences + emoji in one synced reference".

## Decision

`keymap.c` is the single source of truth. Docs are generated from it, never
written by hand. Drift is impossible by construction: a `--check` mode fails
`make test` (and CI) whenever committed output differs from regenerated output.

Settled choices, from the design discussion:

1. **Scope:** one generated reference doc covering layers, combos, leader
   sequences, and emoji — built in two phases (layers first).
2. **Rendering:** ASCII grids in markdown, produced by our own small renderer.
   No `qmk c2json` (currently broken against the local firmware fork:
   "Invalid keyboard.json location"), no keymap-drawer, no dependencies.
3. **In-file schemes:** the ASCII comment inside each `LAYOUT_split_3x6_3(...)`
   call is *also* generated, by the same renderer. The old "resync the comment
   in the same PR" convention is replaced by "run the generator".
   (Known existing drift this fixes: the base-layer comment shows `__` on the
   left thumb where the code has `QK_LEAD`.)
4. **CI:** GitHub Actions with two jobs — host tests incl. the drift check, and
   firmware builds for both keyboards.

## Pipeline

```
keymap.c ──(extract)──> layer model ──(render)──> docs/reference.md
                                     └──(render)──> in-LAYOUT comment blocks
```

One tool: `tools/gen_layer_schemes.py`, following the proven
`tools/gen_unicode_compose.py` pattern (stdlib-only Python, plain-assert test
file, wired into the Makefile).

Modes:

- `--write` — regenerate `docs/reference.md` and rewrite the in-`LAYOUT`
  comment blocks in `keymap.c` in place.
- `--check` — exit 1 with a diff when either output would change. Wired into
  `make test` as `test-schemes`; `make gen-docs` runs `--write`.

## Input contract (what keeps the source generatable)

The extractor reads `layouts/shofel/split_3x6_3/shofel/keymap.c`:

- `enum my_layer_names` — layer identifiers and order.
- Each `[L_X] = LAYOUT_split_3x6_3(...)` initializer — exactly 42 tokens
  (3×12 matrix rows + 6 thumbs), comments stripped, split on commas at paren
  depth 0.
- Each layer's doc comment (`/** ... */` above the initializer) — its first
  paragraph becomes the layer's prose in the generated doc. Hand-written, but
  it lives in the source file, so the reference still has a single home.

Strictness is the enforcement mechanism:

- **Unknown keycode → hard error.** The keycode→glyph map lives in the
  generator: derivation rules for trivial cases (`KC_A`→`a`, `KC_7`→`7`,
  `KC_F1`→`F1`), an explicit table for everything else (`RU_YO`→`ё`,
  `OM_U`→`fwd`, `KC_BSPC`→`⌫`, `KK_MM_POLAR`→`pol`, …). Adding a key to a
  layer without a glyph fails generation — locally and in CI.
- Token count ≠ 42, an unparseable initializer, or a layer missing from the
  enum → hard error with the layer name and position.

## Output contract

### Grid rendering (shared by both outputs)

Canonical form of today's hand-drawn comments:

- 3 rows of 12 cells, then a thumb row of 3+3.
- Wide gap between halves (mimics the physical split).
- `__` = transparent (`KC_TRNS`), `·` = `KC_NO`.
- Per-column width = widest glyph in that column; cells left-aligned.
- Deterministic: same input → byte-identical output.

### `docs/reference.md`

Generated header ("GENERATED by tools/gen_layer_schemes.py — do not edit").
Per layer: heading (layer name), prose (first paragraph of its doc comment),
grid in a fenced code block. Phase 2 appends combo, leader-sequence, and emoji
sections.

### In-file comment blocks

The comment immediately inside `LAYOUT_split_3x6_3(` is replaced with the
generated grid, first line marked as generated. The hand-written doc comments
*above* each layer (design rationale, mnemonics) are never touched. One-time
manual prep in phase 1: move the base layer's "BOO LAYOUT" title and the
Russian layer's fenced block out of the inline comments into doc comments, so
the inline slot is purely generated.

## CI

`.github/workflows/ci.yml`, on push + PR:

- **test** — ubuntu; `make test` (bisect, oneshot, compose, schemes `--check`).
  Needs only gcc + python3.
- **build** — compile `cantor:shofel` and
  `handwired/dactyl_manuform/5x6_5:shofel` against a **pinned upstream
  `qmk_firmware` rev**, overlay-dir pointed at the checkout.
  Open risk: local builds use a fork (`~/workspaces-one/forks/qmk_firmware`).
  If upstream at the pinned rev fails to build the keymap, pin the fork
  instead. The first CI run resolves this.

## Testing

Strict TDD for the generator (repo guardrail): every extractor/renderer
behavior gets a failing test first in `tools/test_gen_layer_schemes.py`,
plain-assert style like `test_gen_compose.py`. Key cases: token split at
depth 0, comment stripping, 42-token enforcement, unknown-keycode error,
glyph derivation vs explicit table, grid alignment (golden sample), `--check`
drift detection on a mutated copy, `--write` idempotence (second run is a
no-op).

## Non-goals

- SVG/keymap-drawer rendering (possible later add-on reading the same
  extracted model; blocked on c2json anyway).
- Generating the C arrays from an external layer definition (source stays C).
- TODO #5 "draw the layers diagram by hand" stays a separate creative item.
