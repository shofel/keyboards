I verified the source geometry and measured one public corpus.

  4. Keep controls and unfinished product ideas separate

    Current left NUM/SYM: tap-toggle under 200 ms, hold/chord momentary. Right Return/Space: ordinary taps; holds open SYM/NUM at native timeout, with Space-swipe arbitration. Their exact locations stay fixed. For right-hand NUM digits, use left NUM; for left-hand symbols, right Return hold frees the left thumb. Opposite-hand holds do not grant a thumb a second simultaneous contact; a symbol on the holding thumb's side may need a latched layer instead.

    Shift remains the current alphabet control. The draft discusses moving it, but the location/semantics are unresolved. No digits on letters, double-space period, Dvorak apostrophe, NUM punctuation changes and BOO/QWERTY replacement are draft directions, not implemented baseline behavior. This proposal neither implements nor decides them. If digit popups are retained, their column-order choices should be kept separately from the three Russian popup defaults.

    Punctuation and layer actions are not scored as if they vanished: they are explicitly outside this letter-and-space corpus comparison. There is no direct punctuation on either compared Russian alphabet. Actual punctuation/layer frequency and Shift interactions require a suitable phone-use corpus; rare-letter popup movement/time also remains unmeasured.

    You should see: preserved current access, with no speculative Shift or layer change smuggled into the proposal.

  5. Read the posture sensitivity before treating this as better

    The search assumes two-thumb portrait typing, no cross-gap reaches, equal targets and bottom-center anchors: left column 3/right column 3 at the bottom alphabet row. It uses Euclidean touch travel, not physical-key actuation or measured thumb biomechanics. No phone model, millimeters, dp, hand size or actual grip is asserted.

    Changing vertical/horizontal pitch ratio from 0.7 to 1.3 retains the complete-path reduction: 10.7–13.9%. But with both assumed rest anchors one column nearer the center gap at ratio 0.7, reach becomes 1.253 → 1.286u (2.6% worse). At the nominal aspect ratio this posture gives only a 4.0% reach reduction, versus 25.9% with central anchors. Physical reach can change the recommendation.

    Equal-size targets mean this study does not estimate accuracy or target-acquisition time. Bigger letters do not create bigger hit targets. On a narrow phone, five targets per half may be a reach/precision compromise that moving letters cannot repair. Maximum observed thumb jump is unchanged at 4.472u. Learning cost is high: nearly the entire alphabet moves; there is no familiarity-preserving constraint or claimed global optimum.

    You should see: a promising model candidate, not permission to replace a QA-passed keyboard.

Evidence, reproduction and limits

Corpus: UD Russian-GSD r2.15, wiki genre. Treebank README lists contributors Ryan McDonald, Vitaly Nikolaev and Olga Lyashevskaya and CC BY-SA 4.0; underlying text rights are distinct from Google annotations. This is encyclopedic public prose, not Slava's phone typing or the historical corpus.

For each # text field: lowercase; replace each maximal non-Russian-letter run with one space; strip sentence edges; preserve ё/ъ/э; count all remaining unigrams and adjacent pairs within each sentence. No punctuation is bridged without a space. Search uses train only: 3,849 sentences, 409,519 characters, 405,670 pairs. Unseen test: 601 sentences, 62,361 characters, 61,760 pairs. Uppercase is normalized and Shift cost omitted equally. No private prompts were opened, extracted or reported.

Search objective: adjacent same-thumb distance + 0.25×mean anchor reach + 0.35×same-thumb different-target rate + 3×(right load−0.5)² + H×popup-letter rate. H=3 abstract units (not milliseconds); evaluated H=1,3,6. Popup target modeled at parent center, extra movement unknown. Equal popup incidence makes this sensitivity a common additive offset, not evidence validating popup latency. The whole-thumb path check is held-out evaluation, not the optimized objective. Width and vertical ratios are geometric proxies; no Fitts-law time coefficients or accuracy model were fitted.

Search: seed 20261102, three restarts × 12,000 swaps. Not an exhaustive optimum; weighted-score reduction is not a measured speedup. Candidate was selected using train only; all nine aspect/hold checks and nine aspect/anchor checks are in the results. Public source bytes are identified by SHA-256 in counts; re-downloading checks the test digest. Branch tags can theoretically move, so the saved digest binds this run.

Artifacts: study.py, evaluate.py, counts/provenance, all results, report renderer. Reproduce from this directory: nice -n 15 python3 -B study.py && nice -n 15 python3 -B evaluate.py && python3 -B render_report.py. Check available memory and coordinate before running. This run had 13 GiB available. Source digest, alphabet uniqueness/completeness, test character totals, finite metrics and same-target/same-thumb consistency assertions passed.

Source review only: no app-source edits, generated Android resources, device input/gestures/screenshots, installation, firmware edits, flashing, merge or deployment. The independent Cantor candidate was inspected read-only and is not reused as thumb evidence. Supported browser access returned 401 before filesystem context was supplied; no authentication bypass was attempted. Web search was unavailable; no unsupported literature claims are made.
