Cantor · L_RU_OPT · leader → (r+n)

A balanced ЙЦУКЕН alternative

A second Russian layer for the Cantor, placed by simulated annealing against this keyboard's own typing — 82,357 Cyrillic letters — and its published effort model. The goal was BOO's roll-feel without its annoying (досадные) SFB. It reaches the highest roll rate and the lowest same-finger rate of any candidate at once, and lives alongside stock ЙЦУКЕН — each a leader-chord away.

01 The layout

Keycaps are tinted by the board's comfort score — darker brass = an easier key — so the frequent letters visibly sit on the strong keys. The finger each column belongs to is the colored underline; the index and inner columns share the index finger, which is the crux of the exercise. ъ (dashed) sits on the reclaimed outer-pinky home key, so every letter is a single press — no combo.

03 The same-finger proof

Same-finger transitions per word — the pain you feel as a stutter. On stock ЙЦУКЕН, какие is all five keystrokes on one finger. On the balanced layout every one of these drops to zero.

04 How it ships

CoexistsShipped as a second layer, L_RU_OPT. Stock ЙЦУКЕН (L_RUSSIAN) is untouched, so muscle memory and the balanced layout are both available — no forced relearning.
ActivatePress leader, then the r+n chord — exactly the mechanism the r+v (vim) / r+w (Windows) backend chords already use. A gated combo emits a token the armed leader captures, so it can't misfire on "turn"/"born". Compose backend.
The tradeIt tilts alternation into rolls (49% vs the baselines' ~70%) — the balanced choice, not roll-first. SFB stays the heaviest penalty, so one same-finger bigram is never traded for a roll; the annoying SFB can't sneak back.
StatusFirmware compiles (39,592 B) and make test is green. Not yet flashed — expect to type Russian slowly on it until it's in the fingers.
